Background

Robotic-assisted surgery is now standard for many urological procedures, and the Hugo RAS system (Medtronic) was introduced to the MENA region at BDF Royal Medical Services for procedures including radical prostatectomy, partial and radical nephrectomy, and pyloroplasty. Despite this, no dedicated artificial intelligence benchmark exists for surgical video from this platform.

Surgical instrument detection, identifying and localising instruments within the operative field, has applications in automated operative reporting, surgical training and assessment, and context-aware robotic assistance. Most existing surgical AI work has focused on laparoscopic and da Vinci platform footage. The Hugo RAS system differs in optics, instrument design, and camera system, and this domain gap has not yet been characterised. This project aims to help address that gap using a dataset of de-identified robotic urological surgery video from BDF Royal Medical Services.

Objectives

  • Establish an annotated surgical dataset from the Hugo RAS platform, with instrument bounding box annotations across radical prostatectomy, partial and radical nephrectomy, and pyloroplasty cases.
  • Develop a deep learning detection model using a YOLOv8 backbone, trained on the curated dataset.
  • Evaluate the model using standard detection metrics (mAP@50, precision, recall, F1-score per instrument class).
  • Assess how well the model generalises across different procedure types.

Methods

  1. 1

    Frame extraction

    Frames sampled from source video at fixed intervals to build a representative set for annotation.

  2. 2

    Annotation

    Instrument bounding boxes labelled using CVAT, with instrument classes defined in consultation with Dr. Ayman Raees to reflect instruments relevant to Hugo RAS urological procedures.

  3. 3

    Model development

    Detection model built on a YOLOv8 backbone, implemented in Python with PyTorch.

  4. 4

    Evaluation

    Model performance assessed on a held-out test set using mAP@50, precision, recall, and F1-score per instrument class.

Current Status

Annotation is currently in progress, working toward a target instance count for each of the two dominant instrument classes. Validation tooling has been built alongside the annotation pipeline to track per-class progress and cross-check against source logs.
